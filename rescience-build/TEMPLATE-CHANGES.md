# The ReScience C article source, and what we changed in it

This directory holds the LaTeX source of the submitted article. It is a copy of the ReScience C
article template from <https://github.com/rescience/template> (master, fetched 2026-10-11) with our
content and a small number of template fixes.

## Files we modified, and why

**`rescience.cls` (4 lines changed).** `\lhead` used `\articleTITLE`, the full 160-character title,
which wrapped to two lines on every page and collided with the `UNDER REVIEW` box in `\rhead`. It now
uses a short running title, `\articleSHORTTITLE`, which we define in `metadata.tex`.

**`header.tex` (7 lines changed).** Two defects in the upstream file:

1. It references `\codeSWH`, which the shipped `metadata.tex` never defines, so the master branch
   does not compile out of the box. We define it.
2. The "Code is available at …" line emitted a sentence-ending period from both the `codeDOI` and the
   `codeSWH` branch, so three of the four empty/set combinations were wrong — empty and empty gave
   `..`, set and empty gave `x..`, and empty and set put a period mid-sentence. Each optional clause
   now emits no terminator and one period closes the sentence once, which is correct in all four.

**`article.tex` (18 lines changed).** Shims the template does not provide because it expects
hand-written LaTeX rather than converted markdown: `booktabs`, `longtable`, `xurl`,
`\providecommand{\tightlist}`, `\providecommand{\real}`, a dummy `none` counter for the `LTcaptype`
that pandoc emits on uncaptioned tables, and `\emergencystretch` to stop a long URL being
letterspaced in the bibliography.

**`metadata.tex` (55 lines) and `metadata.yaml` (155 lines).** Our article's metadata. `metadata.tex`
is written directly rather than generated by `yaml-to-latex.py`, which needs PyYAML; the generated
file is only `\def` lines. It also defines every macro `rescience.cls` and `header.tex` reference,
which we found by diffing the template's own macro uses against what the shipped `metadata.tex`
provided — eight were missing.

**`bibliography.bib` (117 lines) and `content.tex` (1052 lines).** Entirely our content.
`content.tex` is generated from the markdown sources by `build_paper.py` plus pandoc; do not edit it
by hand, edit `../SECTIONS-DRAFT.md` and `../RESULTS-DRAFT.md` and rebuild.

## Building

Use `../build_article.sh`, which pins `SOURCE_DATE_EPOCH` so the PDF is byte-reproducible. Running
`latexmk` directly also works but gives a different hash on every run, because LuaTeX stamps the
build time into the file.

Requires TeX Live 2026 and biber 2.21. A mismatched biber and biblatex will fail with a control-file
version error rather than a useful message.
